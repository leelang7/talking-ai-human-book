## 한 번에 전부 돌리기

```bash
python scripts/gates.py            # 원고 + 회귀 테스트 + 스모크
python scripts/gates.py --quick    # 원고만
```

명령을 여섯 개로 나눠 두면 결국 안 돌립니다. 종료 코드 0 = 전부 통과.

**주의** — 원고 도구가 출력하는 `[FAIL]` 은 *보고된 지적* 이지 게이트 실패가 아닙니다.
초판 러너는 이 둘을 섞어 세서 *"2건 실패"* 와 *"전부 통과"* 를 동시에 찍었습니다.

## 실행 원칙 — 모든 스크립트가 지키는 것

**GPU 없이 되는 것은 GPU 없이.** `_lib`, `ch07_latency`, `ch09_verify` 는 ffmpeg 만 있으면 돕니다.

**게이트는 종료 코드로.** 검증 스크립트는 통과 0, 실패 1 을 반환합니다. 그대로 파이프라인·CI 에 겁니다.

**침묵하지 않습니다.** 오래 걸리는 단계는 진행 상황을 흘려보냅니다. 4분간 아무것도 출력하지 않는 스크립트는 멈춘 것과 구분되지 않습니다 (Ch28 §4).

**실패하면 그 자리에서 죽습니다.** 단계마다 결과를 확인하고, 없으면 즉시 중단합니다. 조용히 빈 파일을 내보내는 것이 최악입니다.

**한글 경로를 코드가 처리합니다.** 사용자에게 파일명을 고치라고 하지 않습니다 (`_lib/paths.py`).

## `_lib` — 공용 모듈

### `paths.py` — 한글 경로 회피

부록 F 실패 14번을 코드로 막습니다. OpenCV 는 Windows 에서 한글 경로를 조용히 실패합니다. **에러가 안 나서 더 위험합니다.**

```python
from paths import AsciiWork, imread_any

with AsciiWork("outputs") as w:
    src = w.take("입력/하늘이.jpg")        # -> work/a1b2c3d4.jpg
    # ...파이프라인은 전부 work/ 안에서...
    w.deliver(result, "하늘이_추모.mp4")   # 최종만 원하는 이름으로
```

`imread_any()` 는 바이트로 읽어 메모리에서 디코딩합니다 — 경로를 라이브러리에 넘기지 않습니다.
원본과 대상이 같으면 복사를 건너뜁니다 (실패 17번).

### `media.py` — fps 와 mux

```python
import media
media.probe(path)                       # 길이·fps(원분수)·해상도·샘플레이트·채널
media.normalize_audio(src, dst)          # 16kHz 모노 (Ch03 §6)
media.mux(video, audio, out)             # ★ 입력 앞 -r 로 fps 재해석 (Ch14 §4)
media.make_idle_loop(src, out)           # 원본+역재생 이어붙이기 (Ch08 §2)
media.check_lengths(video, audio)        # 길이 대조 게이트 (Ch14 §6)
```

**`FPS` 상수 하나를 파이프라인 전체가 참조합니다.** 분수로 다룹니다 — `30000/1001` 을 소수로 반올림하면 긴 영상에서 오차가 누적됩니다.

`mux()` 는 **setpts 로 늘리지 않습니다.** 증상을 덮고 프레임 타이밍을 왜곡하기 때문입니다.

## `ch07_latency` — 지연 예산

```bash
python budget.py          # 40턴 시뮬레이션 → p50/p95 리포트
python test_chunker.py    # 회귀 테스트 9종 (종료 코드 0 = 통과)
```

`LatencyLog` 는 다섯 단계(입력·STT·LLM 첫 문장·TTS 첫 청크·재생)를 찍고 **p95** 를 냅니다. 평균은 나쁜 경험을 숨깁니다.

`stream_sentences()` 의 설계 하나는 **실제 버그에서 나왔습니다.**

> 최소 길이 규칙을 첫 청크에도 적용하면 "네." 같은 짧은 응답이 다음 문장을 기다리느라 늦어집니다. TTFA 를 재겠다고 만든 장치가 첫 소리를 늦추는 셈입니다.
> → **첫 청크는 지연 우선(즉시), 두 번째부터 매끄러움 우선(합침).**

그리고 최소 길이에 걸렸을 때 첫 경계에서 판단을 멈추면 짧은 문장이 앞에 낀 응답이 영원히 안 잘립니다. 기준을 채우는 *가장 이른* 경계를 찾아야 합니다. 두 케이스 모두 테스트로 고정해 두었습니다.

## `ch09_verify` — 싱크 검증

**이 책에서 가장 중요한 스크립트입니다.**

```bash
python verify_sync.py 결과.mp4 --audio 음성.wav --top 15
python verify_sync.py 결과.mp4                      # 내장 오디오 사용
echo $?                                             # 0 = 통과
```

측정하는 것은 **발화구간 × 입 활발도 상위 N프레임 적중률** 입니다.

측정하지 **않는** 것은 `corr(입 벌림, 음량)` 입니다. 진짜 립싱크는 음소에 맞추므로 이 상관은 원래 0에 가깝습니다. 저자는 그 숫자를 올리려다 프레임 재배열·시간워핑·보간 외삽을 만들었고 전부 버렸습니다 (부록 F 18번).

실패하면 확인 순서를 함께 출력합니다 — 드라이버가 클로즈업인가 / 끝부분이 밀리는가 / 소스가 계속 말하는 영상인가.

**의존성**: `opencv-python`, `numpy`, ffmpeg.

## `ch27_eval` — 평가 하네스 (자기비판 C1 해소)

Ch27 이 방법론만 있고 실물이 없다는 지적을 닫는 폴더입니다.

```bash
python score.py --demo                                   # 채점기 자체 점검
python score.py --responses r.json --baseline base.json  # 회귀 게이트
```

**골든셋 20문항** — 일상 4 · 도메인 4 · 모르는것 3 · 경계 3 · 붕괴유도 4 · 기억 2(후속 대화 포함).
Ch22 §4 가 말한 네 가지 붕괴 상황이 *붕괴유도* 분류에 그대로 들어 있습니다.

**채점은 코드 넷 + LLM 훅.** 말투·분량·형식·규칙은 정규식으로 끝납니다. 사실성·거절 적절성·
일관성만 LLM 이 필요합니다. **코드로 되는 것을 LLM 에게 시키지 않습니다**(Ch27 §3).

실측으로 확인된 것 하나 — 말투를 붕괴시킨 응답 세트를 넣었더니 **종합 점수는 0.881 → 0.863
으로 0.018 밖에 안 떨어졌는데, 항목별로 보니 세 분류가 회귀** 했습니다.

> 종합 점수 하나만 보면 놓쳤을 회귀입니다. Ch27 §5 의 *"항목별로 비교하라"* 가 여기서
> 숫자로 증명됩니다.
